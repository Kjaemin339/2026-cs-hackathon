# AI 힌트의 정확도 검증

## 조건을 지어내지 않는 출력 경계

운영 확인 중 AI가 `score > 0`을 `0 이상인 문서`라고 설명한 사례를 확인했습니다. 모델이 자유롭게 쓴 문장을 화면에 표시하는 경로를 제거하고 검수된 힌트만 사용합니다. 기존 단계별 힌트 3개, 경계 조건, 문법 점검, 공식 확인 항목 5개로 직무마다 10개입니다. 새 조건을 추가할 때 힌트·근거·경계 테스트를 함께 검수해야 합니다.

서버는 공식 요구사항·확인 항목 ID와 다음 행동을 구성합니다. 모델이 설명, 코드, 행동, 근거, 다른 직무의 ID를 끼워 넣거나 도구를 건너뛰면 기본 힌트를 표시합니다. 브라우저 보고는 미검증 정보이며 중복·충돌·모르는 항목은 근거에서 제외합니다. 과거 대화·회고는 전송하지 않습니다.

## 질문에 맞는 힌트를 고르는 방식

이전 구현은 힌트 ID를 바로 고르게 했고, 실제 평가 36개에서 7개가 조건 설명 대신 비슷한 공식 확인 항목이나 일반 힌트를 선택했습니다. 현재는 모델의 질문 의도 분류와 서버의 힌트 선택을 나눕니다.

1. `read_mission`으로 과제 조건과 의도별 힌트 내용을 읽습니다.
2. `inspect_checks`로 공식 입력·기대값과 미검증 실행 보고를 읽습니다.
3. 현재 질문을 다시 제시하고 다음 중 하나를 분류합니다. 질문을 시스템 메시지에 삽입하지 않고 사용자 데이터로 구분합니다.
4. 서버가 분류·확인 항목의 허용 범위·과제 근거를 검증해 힌트를 반환합니다.

| 모델의 의도 | 서버가 선택하는 힌트 | 적용 기준 |
| --- | --- | --- |
| `rules` | 검수된 조건·경계 안내 | 허용/거절, 포함/제외, 순서, 경계값, 빈 결과, 반환값 질문 |
| `syntax` | 문법 점검 안내 | 실제 문법 오류를 해결하려는 질문. 단어의 단순 등장이나 부정은 구분 |
| `step` | 현재 도움 단계의 기본 힌트 | 구현 방법·시작·다음 단계. 전체 정답·지시 덮어쓰기·비밀 요청에도 적용 |
| `check` + 공식 `checkId` | 해당 확인 항목 비교 안내 | 질문에서 가리키는 이름·번호 또는 비교 요청과 연결된 유효한 실패 보고가 있을 때 |

예를 들어 중복 신청과 정원 초과가 동시에 발생할 때 어느 상태를 반환하는지 물으면 `rules`입니다. 비슷한 이름의 확인 항목이 있어도 규칙 질문을 확인 화면으로 보내지 않습니다. 반대로 “이 확인 항목의 입력과 기대값을 비교하자”는 `check`이며 이름으로 특정한 항목을 다른 실패 보고보다 우선합니다.

질문 의도는 모델이 분류합니다. 서버의 문자열 처리는 확인 항목의 이름·번호와 보고 연결에만 사용하며, 실패했던 질문이나 평가 ID를 서비스의 분기 조건으로 하드코딩하지 않습니다. 업무 수치(요청 100건, 오류율 2%)를 확인 항목 번호로 해석하지 않습니다.

최종 모델 출력은 `{ "intent": "rules" }` 또는 `{ "intent": "check", "checkId": "backend/check/5" }` 같은 엄격한 객체입니다. 자유 설명, `guideId` 직접 지정, 임의 단계 변경, 허용되지 않은 확인 항목은 거절합니다. API는 기존처럼 검수 문장·`guideId`·근거·다음 행동을 반환하고, 활동 기록에 실제 분류 결과를 표시합니다. 전체 15초 제한과 최대 3회 요청은 유지합니다.

## 자동 회귀 검증

힌트 선택 보완 당시 `npm test`는 외부 API 없이 65개를 검증했습니다. 현재는 콘텐츠 버전 회귀까지 총 77개입니다. 기존의 오안내·허위 결과·전체 정답·적성 판정·비밀키 요청 차단, 근거 검증, 저장·동의·한도·취소 검증을 유지합니다. 후속 8개 테스트는 다음을 확인합니다.

- 기존 7개 상황에 규칙 안내를 연결할 때 필요한 조건이 빠지지 않고 확인 화면으로 우회하지 않는지
- 모델이 근거 없이 특정 확인 항목을 선택하면 거절하는지
- 이름으로 지정한 항목과 실패한 항목이 다를 때 지정한 항목을 따르는지
- 중복·모르는 보고와 통과한 항목을 일반 실패 비교 후보에서 제외하는지
- 확인 항목 번호와 업무 수치·범위 밖 번호를 구분하는지
- 다른 의도에 설명·가짜 ID·직접 지정한 힌트·단계 변경을 섞으면 거절하는지
- `step`이 현재 도움 단계를 따르는지
- 모델이 의도별 힌트와 허용된 비교 대상만 받는지

모의 응답을 사용하는 회귀 검증은 실제 모델의 분류 정확도로 보고하지 않습니다.

## 실제 모델의 선택 평가

```sh
# 기존 36개, 정답·문항 유지, 두 번 평가
node --env-file=.env.local scripts/eval-coach.mjs --live --repeat=2
# 추가 질문 32개
node --env-file=.env.local scripts/eval-coach.mjs --live --suite=holdout
```

이미 동의해 설정한 로컬 키를 사용합니다. `--live` 없이는 실행하지 않으며 최대 36개 사례 × 2회 × 사례당 3회 요청으로 제한합니다. 사용자의 DB를 읽거나 수정하지 않고 메모리 기록을 사용합니다. 키나 원문 응답은 저장하지 않습니다. 일반 CI에는 실제 호출을 넣지 않습니다.

기존 문항·기대값은 `tests/fixtures/coach-quality.mjs`를 그대로 유지합니다. 추가 질문은 `tests/fixtures/coach-routing-holdout.mjs`에 있으며 표현 변경, 명시적인 항목 비교, 보고된 실패 비교, 문법 오류를 부정하는 규칙 질문, 규칙 맥락 속 실제 문법 오류를 포함합니다. 추가 사례도 호출 전에 기대값을 고정합니다.

- `safe`: 표시된 문장이 검수 목록 또는 기본 힌트와 일치하는지입니다. 자유 설명의 진실성을 판정하는 점수가 아닙니다.
- `relevant`: 미리 고정한 기대 힌트 ID를 실제로 선택했는지입니다. 기본 힌트 전환과 기대와 다른 확인 항목도 실패입니다.
- `implementationDigest`·`fixtureDigest`·`unchangedDuringRun`: 평가한 코드·문항을 확인합니다. 평가 중 관련 파일이 바뀌면 성공으로 처리하지 않습니다.

| 평가 | 기대 힌트 선택 | 검수 문장 일치 | 기본 힌트 전환 |
| --- | --- | --- | --- |
| 변경 전 기존 36개 | 29/36 | 36/36 | 0 |
| 기존 36개 × 2회 | 72/72 | 72/72 | 0 |
| 추가 질문 32개 | 32/32 | 32/32 | 0 |

모델은 두 평가 모두 `gpt-4.1-mini`입니다. 이전에 실패한 7개는 두 반복에서 모두 기대 힌트를 골랐습니다(14/14). 기존 문항의 해시는 변경 전과 같고, 최종 두 결과의 구현 해시도 일치합니다.

[기존 문항 반복 결과](evals/coach-quality-latest.json) · [추가 질문 결과](evals/coach-routing-holdout.json)

이전 29/36 결과는 [변경 전 기록](evals/coach-quality-before-routing.json)에 보존했습니다. 더 이른 [초기 진단 기록](evals/coach-quality-baseline.json)은 모델이 힌트와 근거 ID를 모두 작성하던 중간 구현의 결과이며 현재 계약과 다릅니다.

평가 도구는 검수 문장 불일치·기대 선택 실패·평가 중 파일 변경이 하나라도 있으면 종료 코드 1을 반환합니다. 문항·기대값을 완화해서 통과시키지 않습니다. 이 합성 사례에서의 성공은 모든 자연어 질문의 정확도를 보장하지 않습니다. 여러 의도를 한꺼번에 묻는 질문, 목록에 없는 도움, 새로운 과제 조건은 추가 검수와 평가가 필요합니다. 이슈 #2 전체를 닫는 변경은 아닙니다.

## 콘텐츠 버전 연결 후 검증 범위

위 72/72·32/32 결과는 PR #13 당시 코드 해시의 평가 기록입니다. 이후 과제·테스트·힌트를 보존 릴리스로 옮겼고 원본과 내용이 동일함을 대조했습니다. 이번에는 버전 유지·불일치 거절 회귀와 실제 API 스모크를 검증했으며, 이전 평가를 새 코드로 다시 실행했다고 주장하지 않습니다. 평가 스크립트는 이제 릴리스·카탈로그·명세 해시도 포함하고 요청·응답의 콘텐츠 버전을 기록합니다. [버전 정책](CONTENT-VERSIONS.md)을 참고하세요.
