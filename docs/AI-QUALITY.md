# AI 힌트의 정확도 검증

## 이번 변경의 경계

운영 확인 중 AI가 `score > 0`을 `0 이상인 문서`라고 설명한 사례를 확인했습니다. 프롬프트에 주의를 추가하는 것만으로 조건의 역전을 막기 어려워, 모델이 자유롭게 쓴 문장을 화면에 표시하는 경로를 제거했습니다.

현재 모델 출력은 `{ "guideId": "ai/boundaries" }`처럼 검수 힌트 ID 하나뿐입니다. 추가 `message`·참조·행동 필드, 다른 직무의 ID, 없는 ID, 근거 도구를 건너뛴 응답은 거절하고 기본 힌트를 표시합니다. 요구사항·확인 항목 ID와 다음 행동은 서버가 힌트 목록에서 가져오며, 현재 과제에 실제로 있는 근거인지 검증합니다. 모델은 근거 내용을 바꿀 수 없습니다.

힌트 목록은 기존 단계별 힌트 3개, 경계 조건, 문법 점검, 공식 확인 항목 5개로 직무마다 10개입니다. 경계 조건에는 0점 제외, 정원과 같은 인원 제외, 중복 신청 우선, 취소 제외 후 중복 제거, 관리자 타인 기록 삭제 거절, 배포 기준의 초과·미만·같음이 포함됩니다. 새 과제나 조건을 추가할 때 목록과 경계 테스트도 함께 검수해야 합니다.

브라우저 실행 보고는 신뢰할 수 있는 서버 실행 결과가 아닙니다. 알려진 이름의 단일 보고만 연결하며, 모르는 항목과 중복·충돌 보고는 근거에서 제외합니다. 화면에는 ‘보고된 항목 수 / 공식 항목 수’를 표시하고 통과 수를 새로 계산해 단정하지 않습니다. 과거 대화나 회고는 전송하지 않습니다.

## 자동 회귀 검증

`npm test`는 외부 API 없이 실행합니다. 이번에 추가한 16개 테스트는 다음을 확인합니다.

- 실제 관측한 0점 포함 오안내, 허위 실행 결과, 전체 정답, 적성 판정, 비밀키 요청을 JSON으로 반환해도 화면 응답에 섞이지 않는지
- 유효한 ID에 잘못된 문장을 덧붙여도 거절하는지
- 다른 직무·가짜·중복·맞지 않는 참조와 도구 생략을 거절하는지
- 빈 보고·부분 보고·모르는 항목·충돌 보고를 통과 수로 오인하지 않는지
- 30개 공식 확인 상황의 안내가 실제 항목을 참조하고 확인 화면으로 이어지는지
- 여섯 직무의 검수 경계 문장과 독립적인 경계값 실행 기대가 일치하는지
- 코드와 질문 합계 20,000자 제한

기존의 동의·사용 한도·시간 제한·취소·저장·실행 근거 검증을 합해 57개입니다. 이 검증은 허용되지 않은 설명을 차단하는 서버 경계를 확인하며, 실제 모델이 질문에 맞는 힌트를 선택했다는 증거로 사용하지 않습니다.

## 실제 모델의 선택 평가

```sh
node --env-file=.env.local scripts/eval-coach.mjs --live
```

실제 호출에 동의해 설정한 로컬 키를 사용합니다. `--live` 없이는 실행하지 않으며 최대 합성 사례 36개, 사례당 최대 3회 요청입니다. 사용자의 DB·회고를 읽거나 수정하지 않고 별도의 메모리 기록을 사용합니다. 키나 원문 응답은 결과에 저장하지 않습니다. 일반 CI에는 실제 호출을 넣지 않습니다.

고정 사례는 `tests/fixtures/coach-quality.mjs`에 있습니다. 각 직무별로 경계값, 빈 결과 또는 조건 우선순위, 미완성 코드, 문법 오류, 전체 정답 요구, 코드·질문의 지시 덮어쓰기를 평가합니다. 빈 회고는 현재 코치 입력이 아니며, 빈 질문은 API 검증 단계에서 거절합니다.

평가 지표를 분리합니다.

- `safe`: 표시된 문장이 현재 과제의 검수 목록 또는 기본 힌트와 정확히 일치하는지입니다. 모델 설명의 진실성을 별도 판정하는 점수가 아닙니다.
- `relevant`: 미리 고정한 기대 힌트 ID를 실제 모델이 선택했는지입니다. 기본 힌트로 전환되면 실패로 셉니다. 기대와 다른 공식 확인 항목을 선택해도 엄격하게 실패로 남깁니다.

[최근 결과](evals/coach-quality-latest.json): `gpt-4.1-mini`, 36개 중 검수 문장 일치 36개, 기대 힌트 선택 29개, 기본 힌트 전환 0개입니다. 남은 7개는 경계 설명 대신 확인 항목 또는 일반 힌트를 선택했습니다. 잘못된 조건을 새로 작성해 보여주지는 않았지만 질문의 세부 조건을 충분히 설명하지 못할 수 있습니다. 재평가 시 결과는 달라질 수 있습니다.

[초기 진단 결과](evals/coach-quality-baseline.json)는 모델이 힌트 ID와 근거 ID를 모두 작성하던 중간 구현의 결과입니다(기대 선택 17/36, 기본 힌트 전환 7개). 최종 구현은 모델 출력 필드를 ID 하나로 줄이고 서버가 근거를 붙입니다. 두 결과의 출력 계약이 다르므로 모델 자체의 성능 비교로 해석하지 않습니다.

평가 도구는 검수 문장 일치 또는 기대 선택이 하나라도 실패하면 종료 코드 1을 반환합니다. 현재 결과의 선택 관련성 7건을 숨기거나 통과 기준을 완화하지 않았습니다. 서버 경계의 자동 테스트 통과와 이 실제 선택 평가 결과를 구분해 PR에 기재합니다. 이슈 #2 전체를 닫거나 모든 질문에 대한 정확도 해결을 주장하지 않습니다.
